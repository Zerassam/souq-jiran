# محاولة التأكيد الحي الأولى عبر Firebase SMS

## النطاق

تمت التجربة في معاينة مشروع سوق الجيران بعد أن أكد المالك إسناد Firebase Custom Claim بالمفتاح `role` والقيمة `authenticated` إلى أول UID حقيقي. بعد الحصول على موافقته الصريحة، ضُغط زر **«تسجيل الدخول»** في واجهة التحقق الهاتفي.

## النتيجة

أعادت Firebase إلى الواجهة الخطأ التالي:

> `Firebase: Error (auth/internal-error).`

لم تكتمل جلسة Firebase في هذه المحاولة، ولذلك لم يُنفذ بعد اختبار تجديد ID token أو استدعاء إجراء Supabase المؤمّن لتأكيد ربط الهاتف. لا تُسجل هذه الوثيقة رقم الهاتف أو رمز SMS أو كلمة المرور؛ فهي بيانات حساسة لا ينبغي إدراجها في ملفات المشروع.

## الإجراء التالي

يلزم تشخيص سبب الخطأ، مع التركيز على الفصل بين تدفق الدخول التقليدي بالحساب وتدفق Firebase Phone Authentication، ومنع إعادة استخدام مثيل reCAPTCHA أو إدخال رمز التحقق في الحقل الخطأ. بعد الإصلاح، يعاد الاختبار برمز جديد ثم يفحص JWT المتجدد ومطالبة `role` والربط المؤمّن عبر Supabase.
