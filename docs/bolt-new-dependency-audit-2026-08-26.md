# تقرير تدقيق اقتراح Bolt.new

**التاريخ:** 2026-08-26  
**النطاق:** مراجعة اقتراح إزالة `@builder.io/vite-plugin-jsx-loc` وإضافة `npm overrides`، دون تعديل الشيفرة أو رفع تغييرات إلى GitHub.

## الخلاصة التنفيذية

اقتراح Bolt يحتوي على ملاحظة صحيحة جزئياً: الإضافة `@builder.io/vite-plugin-jsx-loc@0.1.1` تعلن توافقاً مع Vite 4 أو Vite 5 فقط، بينما مشروع سوق الجيران يستخدم Vite 7.3.6 فعلياً. لذلك توجد مشكلة توافق نظرية حقيقية، وقد تظهر عند استخدام مدير حزم صارم أو عند تشغيل أداة خارجية تحاول تثبيت الاعتماديات.

لكن الحالة الحالية للمشروع لا تطابق التغييرات التي وصفها Bolt. فملف `package.json` الحالي ما زال يتضمن الإضافة ويستوردها `vite.config.ts`، ولا يوجد فيه `npm.overrides`. يوجد بدلاً من ذلك إعداد `pnpm.overrides` قائم مسبقاً لضبط `tailwindcss>nanoid`، كما أن المشروع يعتمد صراحةً على `pnpm-lock.yaml` ويدير أوامره عبر `pnpm`. حالة Git الحالية، باستثناء تعديل `todo.md` الخاص بهذه الجلسة، لا تحتوي تغييرات Bolt غير ملتزم بها.

## الأدلة التي تم التحقق منها

| الفحص | النتيجة |
|---|---|
| مدير الحزم | `pnpm`، مع `packageManager` مضبوط في `package.json` |
| ملف القفل | `pnpm-lock.yaml` موجود، ولا يوجد `package-lock.json` أو `yarn.lock` |
| Vite في المشروع | نطاق `^7.1.7`، والنسخة المثبتة فعلياً `7.3.6` |
| JSX-Loc | `@builder.io/vite-plugin-jsx-loc@0.1.1` موجودة في `devDependencies` |
| peer dependency للإضافة | `vite: ^4.0.0 || ^5.0.0` |
| استخدام الإضافة | مستوردة ومفعلة في `vite.config.ts` عبر `jsxLocPlugin()` |
| npm overrides المقترحة | غير موجودة؛ الموجود `pnpm.overrides` خاص بـ `tailwindcss>nanoid` |
| حالة Git | لا تغييرات مصدرية من Bolt؛ التعديل الظاهر كان في `todo.md` فقط |

## التحقق التشغيلي

تم تنفيذ `pnpm install --frozen-lockfile --ignore-scripts` بنجاح، ما يثبت أن ملف القفل الحالي قابل لإعادة التثبيت في هذه البيئة. كما نجحت الاختبارات الحالية: **13 ملف اختبار و80 اختباراً**. ونجح بناء الويب الإنتاجي عبر Vite 7.3.6 وesbuild. ظهر تحذير حجم حزمة JavaScript أكبر من 500 kB وتحذير مرجعي لخطوط `/manus-storage`، وهما تحذيران موجودان في البناء ولا يرتبطان بتعارض JSX-Loc، ولم يتسببا في فشل البناء.

## الحكم والتوصية

لا أوصي بتطبيق تغييرات Bolt تلقائياً، ولا أوصي بإضافة `npm.overrides` إلى مشروع يعتمد على pnpm. كما لا ينبغي حذف الإضافة من `package.json` مع ترك استيرادها في `vite.config.ts`؛ فهذا سيكسر البناء مباشرة. وإذا تقرر لاحقاً معالجة عدم توافق JSX-Loc، فيجب أن يكون ذلك تغييراً متكاملاً ومدروساً: إزالة الاستيراد واستدعاء الإضافة من Vite، إزالة الاعتماد من `devDependencies`، تحديث `pnpm-lock.yaml` بأمر pnpm، ثم تشغيل الاختبارات والبناء وفحص المعاينة.

القرار الآمن حالياً هو **عدم تغيير المشروع** لأن البناء والاختبارات يعملان بالفعل، ولأن الإضافة تُستخدم في بيئة التطوير لتحديد مواضع JSX وليست جزءاً ضرورياً من حزمة الإنتاج. يمكن فتح مهمة مستقلة لاحقاً لإزالتها إن كان الهدف تقليل تحذيرات peer dependency أو تبسيط بيئة التطوير، مع الاحتفاظ بإمكانية التراجع.

## ما لم يتم فعله

لم يتم تعديل `package.json` أو `vite.config.ts`، ولم يتم حذف أي اعتماد، ولم تتم إضافة overrides، ولم يتم تشغيل `npm install`، ولم يتم تنفيذ أي `git push` أو إنشاء commit جديد نتيجة هذا التدقيق.
