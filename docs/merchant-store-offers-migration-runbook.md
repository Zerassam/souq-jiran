# تشغيل ترحيل عروض المتاجر

## الغرض

يُفعّل الملف `supabase/migrations/20260903_merchant_store_offers.sql` نظام عروض المتاجر في **سوق الجيران**. ينشئ جدول العروض وسياسات الوصول المقيدة ودوال الحفظ والمراجعة. لا يضيف بيانات تجريبية، ولا يحذف بيانات قائمة، ولا يغيّر حسابات المستخدمين أو قسائم الإحالة.

> لا تعِد تشغيل ملفات التنظيف أو ترحيلات الإحالات السابقة أثناء هذه العملية.

## التنفيذ

افتح **Supabase Dashboard → SQL Editor** للمشروع الصحيح، ثم انسخ محتوى الملف كاملاً والصقه في محرر SQL وشغّله مرة واحدة. لا يلزم إدخال أسرار أو رموز تحقق أو مفاتيح خدمة في هذا الملف.

بعد النجاح، يجب أن تظهر رسالة نجاح من محرر SQL دون أخطاء.

## تحقق قراءة فقط

شغّل الاستعلام التالي في SQL Editor. لا يغيّر أي بيانات:

```sql
select
  c.relname as table_name,
  c.relrowsecurity as rls_enabled
from pg_class c
join pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public'
  and c.relname = 'merchant_store_offers';

select routine_name
from information_schema.routines
where routine_schema = 'public'
  and routine_name in (
    'merchant_save_store_offer',
    'merchant_pause_store_offer',
    'admin_review_store_offer'
  )
order by routine_name;
```

ينبغي أن يرجع الاستعلام الأول صفاً واحداً بالقيمة `rls_enabled = true`، وأن يرجع الاستعلام الثاني أسماء الدوال الثلاث.

## قبول حي بعد الترحيل

بعد أن ينعكس النشر في الواجهة العامة، نفّذ سيناريو قبول واحداً باستخدام حسابات حقيقية مصرح بها:

| الخطوة | النتيجة المتوقعة |
|---|---|
| تاجر **معتمد** يفتح تبويب «عروضي» ويرسل عرضاً ضمن نافذة زمنية مستقبلية أو جارية | تظهر حالة «قيد المراجعة»، ولا يظهر العرض للزوار |
| الإدارة تفتح «مراجعة عروض المتاجر» وتوافق العرض مع ملاحظة اختيارية | تصبح الحالة «معتمد» |
| زائر يفتح الصفحة العامة ضمن فترة العرض | يظهر العرض في شريط «عروض تجار» فقط، مع اسم المتجر ووسم «عرض تاجر» |
| الزائر يضغط زر الإيقاف ثم الاستئناف أو يضع المؤشر/التركيز على الشريط | تتوقف الحركة وتعود بوضوح، مع احترام إعداد تقليل الحركة في النظام |
| الإدارة توقف العرض | يختفي من الشريط العام، ويظل مرئياً للإدارة والتاجر بحالته |

لا يُفترض أن تظهر عروض المتاجر في قسم «آراء موثقة من المجتمع»، ولا أن تستبدل أو تعدّل قسائم «دعوات ومكافآت».

## ملاحظات الصلاحيات

- لا يستطيع إلا التاجر الذي متجره بحالة `approved` إنشاء عرضه أو تعديله أو إيقافه، عبر دوال قاعدة البيانات المحمية.
- لا يستطيع التاجر اعتماد عرضه ذاتياً أو كتابة حقول مراجعة الإدارة.
- يقرأ الزائر فقط العرض المعتمد ضمن الفترة الزمنية الفعالة ومن متجر معتمد.
- تستطيع الإدارة فقط اعتماد العرض أو رفضه أو إيقافه، مع ملاحظة اختيارية للتاجر.
