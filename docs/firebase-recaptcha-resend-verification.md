# تحقق إعادة إرسال Firebase SMS بعد إصلاح reCAPTCHA

## الإجراء المنفذ

بعد تحميل المعاينة بإصلاح دورة reCAPTCHA، فُتحت بوابة حساب الزبون وأُرسلت محاولة تحقق هاتفي جديدة بموافقة المالك الصريحة. بدأ زر الإجراء بعرض حالة **«جارٍ المعالجة...»** ولم يظهر فوراً خطأ:

> `reCAPTCHA has already been rendered in this element`

## حالة التحقق

لا تعد هذه الملاحظة تأكيداً نهائياً لإرسال الرسالة أو اكتمال الدخول. تُحدّث بعد استقرار طلب Firebase، ثم تُسجل نتيجة الرمز وتجديد Firebase ID token واستدعاء ربط Supabase المؤمّن.

بعد انتظار قصير بقيت الواجهة في حالة **«جارٍ المعالجة...»**. لا يظهر في سجل المتصفح أي خطأ جديد، وبالتحديد لم يعد الخطأ المتعلق بإعادة رسم reCAPTCHA ظاهراً في تلك المحاولة.

## التحسين اللاحق

لا يرسم التطبيق reCAPTCHA بعد الآن على عنصر React الثابت مباشرة. قبل كل طلب SMS، تُزال الجلسة السابقة ويُنشأ عنصر فرعي جديد ذو معرف فريد داخل الحاوية؛ ثم يرتبط `RecaptchaVerifier` بهذا العنصر الجديد فقط. يعالج ذلك حالة احتفاظ Google بسجل داخلي للعنصر القديم حتى بعد استدعاء `clear()`.

اجتاز هذا التحسين 35 اختبار Vitest وبناء الإنتاج. ومع ذلك، يبقى التحقق التفاعلي النهائي على الويب مؤجلاً إلى جلسة متصفح مخصصة: لا يتجاوز التطبيق تحدي Google، بل ينتظر من المستخدم إكماله عند طلبه. لا يؤثر هذا التأجيل في تحقق Firebase SMS الميداني السابق على Android.
